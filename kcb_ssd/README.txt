KCB BANK JUBA MANAGEMENT SYSTEM (PHP + MySQL)
================================================

IMPORTANT
---------
This is an educational/demo application, not a real banking platform. Do not use it to hold real customer funds or sensitive banking data. A production system needs professional security engineering, regulatory compliance, audit controls, backups, monitoring, multi-factor authentication, approvals, and independent testing.

REQUIREMENTS
------------
- XAMPP (Apache + PHP + MySQL/MariaDB)
- PHP 8.0+ recommended
- MySQL InnoDB enabled

INSTALLATION
------------
1. Copy the kcb_bank folder to C:\xampp\htdocs\
2. Start Apache and MySQL from XAMPP Control Panel.
3. Open http://localhost/phpmyadmin/
4. Choose Import and import database/jubakcb_db.sql.
5. Check db.php. Default local XAMPP settings are user=root and blank password.
6. Visit http://localhost/kcb_bank/setup_admin.php once.
7. Save the displayed demo credentials, then DELETE setup_admin.php.
8. Open http://localhost/kcb_bank/
9. Sign in using the demo admin credentials generated by setup_admin.php.

FEATURES
--------
- Role-based dashboard (admin, employee, customer)
- Register customers and create their initial bank account
- Edit/deactivate customer profiles
- Open additional bank accounts
- Deposit, withdrawal and account-to-account transfers
- Transaction history
- Employee/admin creation (admin only)
- Demonstration pages for rollback and transaction isolation
- Prepared statements, password_hash/password_verify, CSRF tokens, InnoDB transactions and row locking for money operations

LIMITATIONS / NEXT STEPS
------------------------
- Demo uses SSP as the display currency; change money() in functions.php if needed.
- The customer transfer screen only lists the customer's own accounts as source, but destination account selection is currently based on the same list. For inter-customer transfers, adjust transfer.php to use a destination account number lookup and validate it server-side.
- No transaction reversal or editing of completed monetary transactions is provided intentionally. Use compensating transactions with audited approvals rather than deleting financial history.
- The admin can create staff accounts, but this starter project does not include password reset, MFA, account freeze UI, or formal approval workflow.
- Restrict access to setup files and use HTTPS in any hosted deployment.
